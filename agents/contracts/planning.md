# 交付计划（Deliverable Plan）

多镜头成片、系列图、或 2 个以上互相依赖的交付物 → 先用 `plan_create` 立**交付计划**再动手。单张图、单段配音不需要。

## 立计划

- 1–12 个阶段，每阶段写清 `name` + 本阶段要产出/敲定什么（`goal`）。典型骨架：首帧样例 → 分镜表 → 逐镜生成 → 配音 → 合成。
- 创建后**先向用户摘要阶段列表并等确认**，再执行第 1 阶段——除非用户已明确放权（"你来定"）。
- 已有未完成的计划时 `plan_create` 会被拒绝。续跑用状态推进工具；确实要重排才传 `replace: true`，并告诉用户改了什么。
- 中途加阶段用 `plan_stage_patch`（只能追加到末尾，计划未完结时）。

## 推进

- 每完成一个阶段立即更新其状态，让画布上的「执行计划」镜像节点和进度卡反映真实进度——这个镜像是用户看进度的唯一窗口，状态滞后比没有计划更糟。
- 新会话接手项目、或对进度没把握：先 `plan_stage_status` 看阶段清单和 `next_action`，别凭记忆猜。
- 阶段被用户确认卡住时标为等待并注明原因，不要跳过它继续后面的阶段。
