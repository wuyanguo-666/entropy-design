# 参考视频复刻

原则：**结论只能来自读到的东西**。视频没读过的部分一律标"推测"；报告里每个判断都要能指回某次工具调用或某张关键帧。

## 第一步 · 取证

1. 视频在画布或用户已上传 → `entropy_media_probe` 拿硬事实（时长/画幅/帧率/音轨有无），再 `entropy_media_analyse` 读语义（主体、场景、动作、镜头、光影、节奏）。
2. 要精细复刻或语义太粗 → `entropy_media_montage` 抽帧拼页：按**每秒 1 帧**起步，每页 12 帧；转场密集的段落加密到逐帧，长视频分多页出。拼图节点与报告节点一起留在画布上。
3. 只有截图或口头描述 → 照样能出报告，但动作、时序、声音全部标注为推测，并告诉用户补视频文件才能升级精度。
4. 用户只丢来 URL → 不承诺抓取，请 TA 把文件放进项目。

## 第二步 · 拆解报告（文本节点）

默认全维度：主体与识别锚点 / 场景 / 动作时间线（秒段）/ 镜头与运镜 / 光影色彩 / 材质风格 / 剪辑节奏 / 声音。用户点名只拆某几项就只做那几项。

写法纪律：每个主体全篇用同一称呼并附可见识别点；描述只用可观察量（景别、机位方向、光源方位、材质名），禁用"电影感""高级""氛围拉满"这类空词充当分析。报告末尾附风险清单：人脸手部、多人身份、图内文字、快速运动、风格漂移——哪些在本项目里做不稳，直说。

## 第三步 · 复刻计划

先 `entropy_list_generation_providers` 看手头通道，按 provider-params 契约的边界编译：

1. **按连续性切组**：主体/场景/动作流不断就并成最长的一组；只有跨场景、主体硬切或通道时长档位（见契约）才断开。
2. 每组五要素：起始画面（= 首帧图内容）、连续动作、可承接的末态、时长/画幅、风险。下一组首帧必须从上一组末态派生（末帧截屏或补画承接帧），写"保持一致"不算数。
3. 每组 prompt 五段式：镜头机位 + 主体动作 + 环境光影 + 风格材质 + 节奏/声音意图；用户给定的镜头顺序与否定项原样进 prompt。
4. 首帧生产：`entropy_image_generate`（画布参考用 `ref_node_ids`；同主体跨组首帧用 `series_count` 锁脸/锁产品身份）→ 用户确认 → 作为 `ref_image` 进 `entropy_video_generate`；要精确收尾的组走 `tail_image`（仅可灵/自定义通道）。
5. 对白/旁白：本项目视频通道不承诺人声——旁白稿 → `entropy_speech_generate` → `entropy_videos_merge` 后期合。

## 执行与验收

- 画布两个文本节点交付：《拆解报告》《复刻计划》（每组：时长/画幅/通道/首帧策略/prompt/风险）。
- 用户只要分析 → 到计划为止，不调生成工具；要生成 → 逐组跑，每组上画布后按 Self-Review 规则质检再进下一组。
- 交付前核对：证据节点在画布上、推测都有标记、prompt 无残留占位符、用户约束一条没丢。

## 如实声明的限制

- 视频通道参考图 = 单首帧（可灵等加尾帧），没有多主体 refs 绑定；多人复杂互动场景先讲清一致性风险。
- 跨镜角色一致靠 series_count 锚定 + 文字描述，做不到逐像素锁脸。
